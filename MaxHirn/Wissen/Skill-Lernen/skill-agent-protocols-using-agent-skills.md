**Zweck:** Orientierungsskill: Entscheidungsbaum (welcher Skill für welche Phase), sechs Kernverhaltensregeln (Annahmen explizit, Verwirrung managen, zurückdrängen wenn nötig, Einfachheit erzwingen, Scope-Disziplin, Verifikation statt Annahme), vollständige Lifecycle-Sequenz für ein Feature (idea-refine → spec → planning → context → source-driven → incremental → tdd → code-review → git → docs → launch). Zehn benannte Failure-Modes.

**Wann nutzen:** Bei Unsicherheit welcher Skill passt. Als Einstieg in die agent-protocols-Sammlung. Als Dauerreferenz für die sechs Kernregeln.

**Lauf:** 2026-10-22, trockenlauf, Aufgabe: Übersicht.

**Ergebnis:** Skill vollständig geladen. ~3 Seiten. Wertvolle Zusammenfassung nach dem Durcharbeiten der gesamten Sammlung — verbindet alle Teile zu einem Ganzen.

**Gelernt:** Sycophancy-Failure-Mode explizit benannt: "Of course!" gefolgt von einer schlechten Idee hilft niemandem. Quantifizieren statt wagen ("~200ms Latenz" statt "könnte langsamer sein"). Lifecycle-Sequenz ist jetzt nachvollziehbar weil alle Teilskills bekannt sind. Failure-Mode 8 ("Dinge entfernen die man nicht vollständig versteht") deckt sich direkt mit BrainFiles-Schutzregel "Quasi-Duplikate vor Löschen verifizieren".

**Grenzen:** Meta-Skill ohne eigene Implementierung. Wert steigt mit Kenntnis der referenzierten Skills — nach diesem Durchlauf der gesamten Sammlung vollständig nutzbar.
