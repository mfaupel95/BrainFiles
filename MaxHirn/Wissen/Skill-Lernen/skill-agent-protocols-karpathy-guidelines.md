**Zweck:** Kompakte Verhaltensrichtlinien abgeleitet aus Andrej Karpathys Beobachtungen zu LLM-Coding-Fallen: 1) Annahmen explizit machen, Unklarheiten benennen. 2) Minimaler Code — keine spekulative Flexibilität, keine unmöglichen Fehlerfälle. 3) Nur anfassen was nötig ist, angrenzenden Code nicht "verbessern". 4) Aufgaben in verifizierbare Ziele übersetzen, kurzen Plan vorausschicken.

**Wann nutzen:** Als Dauerregel — besonders bei komplexen Aufgaben als Checklist vor dem ersten Tastendruck.

**Lauf:** 2026-10-22, trockenlauf, Aufgabe: Übersicht.

**Ergebnis:** Skill vollständig geladen. Sehr kurz (~1 Seite). Destilliert viele andere Skills auf vier Kernregeln.

**Gelernt:** "Jede geänderte Zeile muss direkt auf die Anfrage des Nutzers zurückführbar sein" — guter Selbsttest für Scope-Disziplin. Ergänzt und komprimiert was `incremental-implementation` und `code-simplification` ausführlich beschreiben. Als schnelle Erinnerung vor jeder größeren Aufgabe nützlich.

**Grenzen:** Kein Prozess, sondern Haltung. Keine Werkzeuge, keine Vorlagen. Sehr allgemein — der Wert liegt in der Kürze und dem Merken.
